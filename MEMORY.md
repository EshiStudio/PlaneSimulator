# PlaneSimulator

Веб-приложение (HTML + three.js) с белым клетчатым полем 50×50 (клетка = 1 м) для понимания объёма и перемещения, и моделью самолёта.

- **Godot-проект отменён** — удалены `project.godot`, `scenes/`, `scripts/`, `.godot/`, все `*.import`. Причина: пользователь попросил переделать всё на HTML.
- `index.html` — вся логика: белый пол, сетка (1 м — серые линии, 5 м — тёмные), подсветка клетки под курсором, самолёт из GLB, HUD с координатами.
- `lib/` — локальные three.js (0.170.0): `three.module.js`, `GLTFLoader.js`, `OrbitControls.js`, `BufferGeometryUtils.js` (скачаны с unpkg, работают офлайн). `OrbitControls.js` сохранён, но сейчас не импортируется: камера управляется вручную. ВАЖНО: у `GLTFLoader.js` импорт `BufferGeometryUtils.js` переписан с `../utils/` на `./` — без этого браузер ловит 404 и модель не грузится.
- `assets/stylized_ww1_plane.glb` + текстуры `_0.jpg`, `_1.png` — модель самолёта (персик). Масштаб автоматически подгоняется под ~6 м размаха. Полётные эффекты материалов `Blur_effect` и `lambert1` удаляются; контурная оболочка `Tooner`, выступающая вниз почти на 0.5 м, остаётся видимой, но исключена из расчёта масштаба, посадки и теней. Поэтому bbox опирается на геометрию шасси и ставит её на `y=0`. Самолёт отбрасывает настоящую `PCFSoftShadowMap`-тень на прозрачный `ShadowMaterial`, а свет следует за ним в безграничном мире.

## Управление
ЛКМ с перетаскиванием — орбита камеры вокруг самолёта, колесо — дистанция (камера ТОЛЬКО мышью + Q/E — высота; WASD от камеры убрано), стрелки — самолёт по клеткам, Пробел — запуск/остановка двигателя (пропеллер плавно раскручивается до ~6.4 об/с), F — выпуск/уборка закрылков, R — сброс камеры. Одиночные ЛКМ/ПКМ ничего в мире не нажимают.

## Закрылки
- В модели ЕСТЬ родные светлые (бежевые) панели на задней кромке обоих крыльев: `polySurface161/165` (верхнее крыло) и `polySurface173/174` (нижнее), каждая с контурной оболочкой `polySurface407/408/410/411_Tooner_0`. Пользователь подтвердил: это и есть закрылки — НЕ создавать свои панели!
- Каждая пара (панель+Tooner) прикрепляется через `Object3D.attach` к шарниру `Group`. Ось шарнира НЕ горизонтальна: она проходит вдоль наклонной передней кромки панели — по крайним по X вершинам передней кромки (max z, допуск 0.015) в мировых координатах, затем точка крепления и направление переводятся в локальные координаты модели через `worldToLocal`, а `hinge.quaternion` выравнивается по направлению кромки через `setFromUnitVectors((1,0,0), dir)`. Без этого панель «выкручивается» из крыла (кромки наклонены на ±8–12°).
- Ось шарнира вдоль X; `rotation.x = -flapAngle` отклоняет панель вниз-назад; ход плавный: `FLAP_SPEED = 120°/с`, максимум `FLAP_MAX_ANGLE = 35°`; `flapsOut` переключается по `F`.
- Каждая пара имеет СВОЙ угол отклонения: верхние закрылки `FLAP_MAX_ANGLE_UPPER = 25°`, нижние `FLAP_MAX_ANGLE_LOWER = 35°` (пользователь: «попарно верхняя и нижняя» выглядело как одна пара → выбрал вариант «разные углы отклонения»). `flapGroups` — массив объектов `{group, maxAngle}`, каждый шарнир анимируется к своему углу в `animate()`.

## Двигатель и пропеллер
- Лопасти винта — меши `polySurface304/305/306` (материал `pasted__lambert2`), контур — `polySurface406_Tooner_0`; диски размытия `Blur_effect` (pCube1/pCube4) удаляются как полётные эффекты.
- Всё собрано в `propPivot` (центр = центр bbox лопастей, через `Object3D.attach`), вращение `propPivot.rotation.z += propSpeed*dt` в `animate()`.
- `PROP_MAX_SPEED = 40` рад/с, `PROP_ACCEL = 18` рад/с² — плавная раскрутка/торможение; `engineOn` переключается по `Space`.

## Запуск
Обязателен HTTP-сервер (ES-модули и GLTFLoader не работают с file://). Сервер уже запущен на порту 8000 из папки проекта:
`python -m http.server 8000` → http://localhost:8000/index.html

## Ключевые факты/решения
- Управление самолётом: `planeGroup` стоит в центре клетки, `planeYaw = Math.atan2(dx, dz)` (модель носом по -Z).
- Модель грузится через `./assets/...` (относительный путь) — менять расположение папок нельзя.
